# AGENTS.md

Правила для автоматических исполнителей и людей, которые работают в этом репозитории.

## Перед началом
1. `git fetch origin && git switch main && git pull --ff-only`
2. Возьмите задачу из issues с меткой `agent-bus` без метки `claimed`. Запишите claim JSON-комментарием: роль, `base_sha`, `lease_until` (+60 мин), `attempt`.
3. Перечитайте комментарии. Если кто-то успел раньше, выберите другую задачу.

## Работа
- Ветка от main: `fix/<ID>-<кратко>` или `feat/<ID>-<кратко>`. База PR — только main.
- Один PR — одна находка. Заголовок: `fix(<ID>): что меняется`.
- Heartbeat в issue каждые 20 минут, пока задача открыта.
- Чужие ветки и `.github/` не меняйте без задачи с меткой `owner-only`.

## Инварианты архитектуры и проверки (2026)
- **Владение вердиктом (`ADR-001`):** `summary.passed` вычисляет только детерминированное ядро (`EvidenceAssembler` + `DeterminismGate`). Выходы LLM/VLM и OCR остаются в контуре `advisory` и не меняют вердикт (`OFF == ON`).
- **Единые точки входа и локальные схемы:** модели IFC открываются только через `open_ifc_model` / `open_ifc_file` / `open_ifc_session` (`ifc_file_open.py`) со сверкой числа экземпляров SPF и `RocksDB`; схемы IDS 1.0 XSD загружаются только через `load_offline_ids_schema` / `ensure_ifctester_offline_schema` (`allow="local"`, без сетевых запросов к `www.w3.org`).
- **Воздержание и калибровка:** при расхождении векторного слоя и OCR на штампах 2D (`stamp_dual_read.py`) возвращается `ABSTAIN` (`requires_hitl=True`); отчёты калибровки (`compute_reliability_report.py`) считают интервалы Уилсона, ECE и оценку Брайера при `publishable=false` вне корпуса заказчика.
- **Десятичная полоса ε и идентичность марок:** `within_epsilon` / `measured_delta` сравнивают измерения через `Decimal`, чтобы двоичный хвост не выталкивал значение за ε. Та же полоса обязательна в сверке объявленных расчётных таблиц. Омоглифы марки стали сворачиваются (`С345` = `C345`, латинская `I` не сворачивается). Короткий список и диапазон марок систем (`В2.7,8,9`, `В2.4–В2.6`) совпадают с одной маркой в `target_ref`. Это не коллизия систем и не чужой scorecard.
- **Единица наблюдения сверки расчёта:** цитируется только тройка `element_id × section_id × parameter_id`. Неполная или разная тройка — `observation_status=NOT_VERIFIED`. `MATCH` объявленных значений не есть корректность расчёта и не пишет `summary.passed`.
- **Кривая воздержания:** `abstention_sweep.py` поднимает порог на учебной фикстуре чертежей. Доля `hitl_required` не убывает. ECE и Бриер без меток исхода не считаются.
- **Ансамбль e-процессов:** `e_process_simulation.py` (LCG, seed `20261018`) сравнивает смесь Вовка–Ванга, степенной калибратор и усечённый aGRAPA с наивным правилом $p < \alpha$. Неравенство Вилля — про долю траекторий, не про одну.
- **Таблицы рукописи:** `manuscript_tables.py` копирует число из пина только при `attested_by=ci` и непустом `claim_level`. Генератор базовой линии ставит `claim_level=fixture_engineering`. Текущий пин это поле не содержит; числа в таблицу не переписываются вручную.
- **Контракт обмена:** `exchange_contract.py` (`1.0.0`) не выпускает находку без `finding_id` и `evidence_refs`. Решение «отклонить / ложное / уточнить» требует заметку. Поле `writes_summary_passed` всегда ложно. Это не импорт в СОД.
- **Дальнейшие прогоны:** автономные модули фаз E/M/P в репозитории закрыты; план разметки E5 считает объём корпуса и держит `n_labeled=0`, `study_executed=false`. Снаружи остаются ручной таймер E1, живая разметка E5, подпись методолога и замена пина артефактом CI с `claim_level`. Дорожная карта: [`docs/quality/ACADEMIC_ROADMAP_2026_09.md`](docs/quality/ACADEMIC_ROADMAP_2026_09.md) и [`docs/plan/REMEDIATION_PLAN_P0_P2_2026_09.md`](docs/plan/REMEDIATION_PLAN_P0_P2_2026_09.md). Checkpoint `GO` (`regulatory_measurement_mvp`); `customer_go` всегда `false` до закрытия RT-001b/c, RT-002c, RT-003c.

## Мердж
Мерджит merge queue после одобрения ревьюера и зелёных проверок. Свой PR не одобряйте. Красный main останавливает все задачи, кроме его починки.

## Чистота
- В коммитах нет трейлеров `Co-authored-by` для ботов и нет фраз вида «generated by».
- В коде нет `print` и `console.log` вне CLI, закомментированного кода, TODO без номера issue, временных файлов.
- В тексте нет личных имён: пишите роль («ревьюер», «владелец»).
- Комментарий объясняет причину, а не пересказывает код.
- Статус работы живёт в issue, а не в файлах репозитория.
