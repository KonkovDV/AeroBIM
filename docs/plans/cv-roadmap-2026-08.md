# AeroBIM CV Roadmap — evidence-first, август 2026

**Принцип:** инженерный чертёж нельзя надёжно проверять одной картинкой и одним запросом к модели. Рабочая система — гибридная: векторные данные и геометрические правила дают доказательство, OCR/VLM помогают найти и объяснить неоднозначные места, эксперт подтверждает спорные случаи. **VLM никогда не меняет `summary.passed`.**

## 1. Почему это сложнее обычного CV

| Уровень | Что в листе | Что теряет VLM при растеризации |
| --- | --- | --- |
| Геометрия | линии, дуги, оси, координаты, масштаб | точная геометрия, координаты, масштаб |
| Символы | двери, окна, приборы, арматура | типы объектов, блоки, атрибуты |
| Текст | марки, примечания, ревизии | единицы, порядок, связи |
| Топология | что с чем соединено | связи между объектами |
| Межлистовые ссылки | узел ↔ подробность ↔ спецификация | внешние ссылки |
| Междокументные связи | чертёж ↔ IFC ↔ ТЗ ↔ расчёт | семантика невидимых слоёв |
| Инженерный смысл | соответствие требованию | контекст проекта |

**Вывод:** растровое изображение ≠ исходный DWG/векторный PDF. Нужны **два представления одновременно**: геометрическое (примитивы, слои, координаты) и визуальное (рендер, OCR, подсветка).

## 2. Бенчмарки и SOTA (август 2026)

| Источник | Что показывает | Практический смысл для AeroBIM |
| --- | --- | --- |
| **AECV-Bench** | 120 планов, 192 вопроса; текст/OCR лучше, подсчёт символов 0.40–0.55 | Модель может прочитать надпись, но не считает двери/окна надёжно |
| **ArchPlanVQA** | CAD→image; семантическая точность ~33–38% | Превращение CAD в картинку теряет структуру |
| **BlueprintSymVL** | Плотные символы, перекрытия, галлюцинации | Реальные листы — не чистые картинки |
| **DrawingVQA** | 33 IFC-листа, 92 экспертных вопроса; разрыв модель↔эксперт | Модель видит объект, но не понимает роль |
| **Enginuity** | Recall@all 0.61–0.87, Token F1 0.03–0.18 | «Нашла фрагмент» ≠ «правильно восстановила содержание» |
| **Blueprint** | Региональный конвейер: области → ограниченный VLM-OCR → нормализация → поиск | Success@3/nDCG лучше, чем чистый VLM |
| **ArchCAD-400K** | 413K фрагментов, panoptic symbol spotting | Обучение на CAD-примитивах, не только растр |
| **VecFormer** | Линейное представление векторных примитивов | Сохраняет геометрическую непрерывность |
| **Text-Aided CAD Symbol Spotting** | Текст как дополнительный сигнал | Марки/подписи помогают символам |

**Главный вывод:** региональный конвейер важнее «самой умной» модели. VLM не должна смотреть на весь лист.

## 3. Целевая архитектура (7 слоёв)

```
Ingestion → Region understanding → Extraction → Structured evidence → Deterministic validation → HITL → Reporting
```

| Слой | Содержание | Инструменты (Aug 2026) | Выход |
| --- | --- | --- | --- |
| 1. Ingestion | PDF text layer, PDF render, raster scan, DXF (позже), IFC, DOCX/XLSX | pdfminer, PyMuPDF, ifcopenshell | Файл + SHA256 + страницы + координатная система + статус пригодности |
| 2. Region understanding | Штамп, спецификация, экспликация, план, разрез, узел, таблица, размерная область | LayoutLMv3 / Donut / DocLayNet, затем небольшой детектор | `RegionAssessment` с типом, bbox, качеством, `HEURISTIC_BASELINE` |
| 3. Extraction | Векторный текст, OCR, геометрический parser, таблица, локальная VLM | RapidOCR, pdfplumber, CAD parser, VLM (advisory) | `StructuredEvidence` с методом, версией, входным фрагментом |
| 4. Structured evidence | Файл, лист, область, координаты, метод, версия, confidence (диагностика), normalized value, единицы, evidence hash | Существующий `DrawingAnnotation` + `ProblemZone` | Evidence envelope (уже частично есть) |
| 5. Deterministic validation | Формат, единицы, диапазон, арифметика, допуск, IFC, спецификация, межлистовая ссылка, норма | Правила, IDS, геометрия | Finding / CHECKED_OK / NOT_CHECKED / REQUIRES_EXPERT |
| 6. HITL | Эксперт видит область, текст, кандидата, доказательство, альтернативы | Существующий review shell | Подтверждение/исправление/отклонение |
| 7. Reporting | Различать: проверено/нарушение/не проверено/недостаточно/требуется эксперт/VLM кандидат/детерминировано подтверждено | HTML/JSON/BCF | Честный отчёт с coverage map |

## 4. Детальный план по фазам (P0–P4)

### P0 — OCR для растровых PDF/PNG (0–2 недели после 11.08)
**Цель:** честный OCR baseline с явным `OCR extraction, not engineering understanding`.

| Шаг | Действие | Артефакт | Метрика |
| --- | --- | --- | --- |
| 0.1 | Подключить RapidOCR к `RasterDrawingAnalyzer` (только raster, не PDF text layer) | `raster_drawing_analyzer` с `ocr_engine_factory` | `CER/WER` на 3–5 fixture-сканах |
| 0.2 | Добавить `quality_flags`: `ocr_used`, `text_layer_available`, `low_confidence` | Evidence envelope | Доля аннотаций с `ocr_used=true` |
| 0.3 | Тест: пустой OCR → `NOT_CHECKED`, не «ошибок нет» | `test_vertical_slice_demo.py` + кейс | Покрытие честных статусов |
| 0.4 | Документация: `OCR extraction, not engineering understanding` | `docs/demo/vertical-slice-2026-08-11.md` | Claim boundary явно в артефактах |

**Риски:** галлюцинации на плотных областях; неверные единицы/десятичные разделители.  
**Guardrail:** OCR только на выбранную область; результат всегда с `confidence` как диагностикой, не доказательством.

### P1 — Stamp/region detector (2–6 недель)
**Цель:** находить штамп, спецификацию, экспликацию, размерную область с метрикой попадания в поля.

| Шаг | Действие | Артефакт | Метрика |
| --- | --- | --- | --- |
| 1.1 | Эвристика: координатные шаблоны (stamp внизу справа, спецификация таблица, экспликация список) | `region_heuristics.py` | Precision/recall на 10 листах (fixture) |
| 1.2 | Небольшой детектор: LayoutLMv3 / DocLayNet fine-tune на размеченных 50–100 областях | `region_detector.onnx` | `mAP@50`, `recall` критических областей (штамп, спецификация) |
| 1.3 | Интеграция: `DrawingRegionRef` с `layout_role`, `hitl_required`, `hitl_reason` | Уже частично есть | Доля регионов с `hitl_required=true` |
| 1.4 | UI: overlay для stamp/title/content (уже есть база) | `DrawingEvidencePanel` | 4 иллюстрации с находкой поверх реального листа |

**Риски:** переобучение на одном стиле оформления; пропуск нестандартных штампов.  
**Guardrail:** `HEURISTIC_BASELINE` статус; эксперт подтверждает нестандартные случаи.

### P2 — Символьное распознавание (6–12 недель, исследовательский контур)
**Цель:** двери/окна/оборудование — не VLM-first, а CAD/vector primitives + image features + text annotations.

| Шаг | Действие | Артефакт | Метрика |
| --- | --- | --- | --- |
| 2.1 | Векторный parser: линии, дуги, блоки, слои, bounding box | `vector_entities` в evidence | Доля объектов с корректной системой координат |
| 2.2 | Кандидаты символов: ArchCAD-400K / VecFormer как reference | `symbol_candidates` | `precision/recall/F1` по классу, `count error` |
| 2.3 | Геометрическая валидация: размеры, пропорции, связи | `geometric_validation` | Доля измерений в допуске |
| 2.4 | Expert review: неоднозначные кандидаты | `hitl_queue` | `human acceptance rate`, `ambiguous-link rate` |

**Риски:** визуально похожие символы, перекрытия, нестандартные варианты.  
**Guardrail:** VLM даёт кандидатов, не окончательный счёт; эксперт решает спорные случаи.

### P3 — IFC mapping (8–14 недель)
**Цель:** связать annotation → IFC element с геометрической совместимостью и допуском.

| Шаг | Действие | Артефакт | Метрика |
| --- | --- | --- | --- |
| 3.1 | Candidate IFC elements по типу/марке/этажу | `ifc_candidates` | `precision` связи annotation→object |
| 3.2 | Геометрическая совместимость: bbox, координаты, допуск | `geometric_match` | Доля связей с корректной геометрией |
| 3.3 | Свойства: pset, quantity, тип объекта | `property_match` | `recall` критических связей |
| 3.4 | Причина выбора + confidence как сигнал маршрутизации | `match_reason` | `human acceptance rate` |

**Риски:** одинаковые марки в разных этажах; неоднозначные соответствия.  
**Guardrail:** `confidence` только для маршрутизации, не для доказательства; эксперт подтверждает неоднозначное.

### P4 — VLM advisory (12+ недель, строго advisory)
**Цель:** VLM помогает найти/объяснить неоднозначные места, но не пишет итоговый PASS/FAIL.

| Шаг | Действие | Артефакт | Метрика |
| --- | --- | --- | --- |
| 4.1 | Только выбранная область: bbox, тип, кандидаты, текстовый слой, координаты | `vlm_input.json` | Доля запросов с полным контекстом |
| 4.2 | Строго структурированный кандидат: JSON schema, не свободный текст | `vlm_candidate` | `field exact match`, ошибки единиц |
| 4.3 | Детерминированная проверка: значение, единицы, допуск | `deterministic_check` | `false positive rate` |
| 4.4 | HITL: эксперт подтверждает/исправляет/отклоняет | `expert_decision` | `human acceptance rate` |

**Риски:** утечка данных наружу; галлюцинации; изменение verdict.  
**Guardrail:** локальный профиль; не отправлять весь лист; VLM не меняет `summary.passed`; при сбое → `REQUIRES_EXPERT`.

## 5. Метрики (без одной общей «accuracy»)

| Категория | Метрики | Что НЕ делать |
| --- | --- | --- |
| **Регионы** | mAP@50, mAP@50:95, recall критических областей, пропуски штампов/спецификаций | Не публиковать одну цифру «CV accuracy» |
| **OCR/текст** | CER, WER, field exact match, нормализованное совпадение, ошибки единиц/десятичного разделителя | Не считать OCR «пониманием чертежа» |
| **Символы** | precision/recall/F1, mAP, count absolute/relative error, false positives per sheet, missed critical symbols | Не доверять confidence score |
| **Геометрия** | ошибка координат/длины/площади, % измерений в допуске, доля корректной системы координат | Не заменять геометрию картинкой |
| **Связи** | precision/recall связи annotation→object, ambiguous-link rate, human acceptance rate | Не считать связь доказательством без допуска |
| **Findings** | precision подтверждённых, recall критических, false positive rate, coverage map, nDCG по приоритету, время до первой полезной находки | Не выдавать fixture за customer accuracy |

## 6. Риски и guardrails

| Риск | Guardrail |
| --- | --- |
| Галлюцинации VLM | Только выбранная область; структурированный кандидат; детерминированная проверка; эксперт |
| Растер = вектор | Два представления: геометрическое + визуальное; векторные данные приоритетны |
| Целый лист в VLM | Региональный конвейер; не отправлять весь лист без необходимости |
| VLM меняет verdict | `summary.passed` только детерминированное ядро |
| Одна цифра accuracy | Набор метрик по категориям; без customer accuracy |
| Переобучение на стиле | Размеченный корпус заказчика; held-out split; контроль дрейфа |
| Плотные/перекрытые области | Экспертная эскалация; `REQUIRES_EXPERT` при неопределённости |

| Фаза | Датасеты | Модели | Конфиги | Отчёты | Тесты | CI gates |

## 8. Первый пилотный пакет (после P0)

**Цель:** один реальный лист заказчика (или максимально близкий fixture) с разметкой.

| Шаг | Действие | Критерий |
| --- | --- | --- |
| 1 | Выбрать 1 лист с штампом/экспликацией | Есть ground truth для 5–10 полей |
| 2 | Разметить области (штамп, спецификация, размерная) | 2 разметчика, kappa > 0.8 |
| 3 | Прогнать P0+P1 | Precision/recall по областям, CER/WER по тексту |
| 4 | Сопоставить с IFC/спецификацией | 1–2 finding с provenance |
| 5 | Экспертная проверка | 100% неоднозначных случаев решены экспертом |
| 6 | Отчёт | Метрики по категориям, без одной цифры accuracy |

## 9. Что НЕ делать (ни в одной фазе)

- Не отправлять целый лист в VLM.
- Не обучать один универсальный классификатор на все дисциплины.
- Не распознавать DWG после грубой растеризации.
- Не генерировать замечание напрямую из изображения.
- Не доверять confidence score как доказательству.
- Не считать двери/окна только моделью.
- Не использовать LLM для измерения расстояний.
- Не проверять нормы через свободный текстовый ответ модели.
- Не заменять IFC/геометрию картинкой.
- Не публиковать одну общую цифру «точности CV».

## 10. Итоговая рекомендация

**AeroBIM не должен строить «VLM, которая понимает строительный чертёж». Он должен строить доказательный конвейер, в котором VLM помогает найти и интерпретировать фрагмент, а инженерное утверждение подтверждается структурированными данными, геометрией, правилами, междокументными связями и экспертом.**

Ближайший срез — штамп или экспликация (уже частично есть). Следующий серьёзный шаг — структурированные CAD-примитивы, региональная обработка и специализированные модели, а не просто увеличение универсальной VLM.
