Процедура приёмки, применимая к **любому** решению (включая AeroBIM). Конкуренты не упоминаются.

## 1. Определения

| Термин | Операциональное определение |
|---|---|
| Находка | машиночитаемая запись с правилом, источником, доказательством |
| Ошибка (TP/FP) | согласие ≥2 разметчиков, что находка верна / ложна |
| Пропуск (FN) | нарушение в эталоне, не попавшее в отчёт |
| Не проверялось | `NOT_CHECKED` / эквивалент — **не** «нарушений нет» |

## 2. Корпус и разметка

1. Held-out корпус фиксируется **до** прогона (хеш комплекта).  
2. ≥2 независимых разметчика; целевое согласие Cohen's κ / Krippendorff α ≥ 0,8 (или task-justified порог с обоснованием).  
3. Споры — в журнал adjudication.

## 3. Метрики (обязательный минимум)

- Precision, recall, F1 **по классам ошибок** + макро.  
- Учёт FN обязателен.  
- Интервалы Уилсона на долю.  
- nDCG — если есть ранжирование замечаний.  
- Время: cold/warm отдельно; отпечаток машины + версия кода + хеш комплекта.

## 4. Нейтральный обменный формат

JSON-массив:

```json
{
  "finding_id": "…",
  "class": "…",
  "sheet_or_element": "…",
  "norm_ref": "…",
  "expert_verdict": "tp|fp|fn|disagree"
}
```

Один и тот же код метрик должен принимать отчёт любого участника (`compute_quality_protocol_stats --vendor-agnostic` — целевой CLI).
