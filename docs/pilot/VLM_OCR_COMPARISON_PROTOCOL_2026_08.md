# Протокол сравнения VLM для распознавания инженерных документов

**Окно исполнения:** 4–20 августа 2026 (после выхода весов Kimi K3 — 27 июля).
**Связанные SSOT:** [`PARALLEL_WORKPLAN_CHECKPOINT2_2026_08.md`](PARALLEL_WORKPLAN_CHECKPOINT2_2026_08.md),
[`../quality/CUSTOMER_PILOT_BACKLOG_2026_07_21.md`](../quality/CUSTOMER_PILOT_BACKLOG_2026_07_21.md) (P3: GraphRAG/IfcLLM product — **forbidden**; VLM — advisory).

## Академические якоря (июль 2026)

| Домен | Якорь | Что переносим |
|---|---|---|
| Бенчмарк инженерных диаграмм | **Enginuity** (arXiv 2606.03410, Jun 2026) — 2 056 пар «диаграмма↔таблица», 4 frontier-VLM | Дизайн задач, метрики с пенализацией за пропуски, каталог failure modes |
| Ключевой результат Enginuity | Recall@all 0.61–0.87, но Token-F1 описаний **0.03–0.18**; Qwen3-VL-32B по recall статистически неотличим от Claude Opus 4.7 (перекрывающиеся CI) | VLM находит объекты, но **перефразирует** обозначения → сырой вывод VLM никогда не идёт в правила без нормализации |
| Метрики | Enginuity: token-overlap занижает качество в 2–6× против semantic similarity; LLM-judge при n=60 статистически неразличим (ширина CI ≈1 балл) | Двойная метрика (exact/token-F1 **и** semantic), LLM-judge не используется для выбора |
| Судья ≠ истина | ChartMuseum (Tang et al. 2026) — LLM-judge маскирует перцептивные ошибки | Спорные случаи — только human adjudication |
| Статистика сравнения | Waves K–M: cluster bootstrap CI, paired permutation + Holm, TOST | Ранжирование моделей — через `compare_extraction_runs` (p-value + Holm), не по точечным числам |
| Прецедент | SeePhys (Xiang et al. 2026): frontier-VLM <60% на структурных научных диаграммах | Ожидания калиброваны: строительные чертежи ещё сложнее (нет доменной лексики в pretraining) |

## Кандидаты (пиновать снапшоты после 27.07)

| Модель | Веса / лицензия | Локальный запуск (закрытый контур) | Примечания |
|---|---|---|---|
| Qwen3-VL (32B Instruct) | Открытые | vLLM, 1×H100 80GB (подтверждено Enginuity) | OCR 32 языка, заявленная устойчивость к blur/tilt/low-light |
| Kimi K3 / Kimi-VL | Веса обещаны к 27.07.2026 (Modified MIT) | **Под вопросом:** K3 = 2.8T MoE — вероятно вне пилотного железа; тогда тестируем только младшие Kimi-VL варианты | Дисквалификация из пилота, если ни один вариант не запускается в контуре |
| Gemma (4-26B или 3) | Открытые | vLLM, 1×H100 (fp8 подтверждено Enginuity) | В Enginuity слабейшая по описаниям (Token-F1 0.058) — проверить на нашем корпусе |

**Fail-closed правило:** модель без подтверждённого локального запуска в закрытом контуре
не участвует в выборе для пилота независимо от качества (требование режима обработки данных).

## Задачи (адаптация Enginuity к контуру AeroBIM)

| # | Задача | Вход | Ground truth | Основная метрика |
|---|---|---|---|---|
| T1 | Штамп листа (title block): шифр, лист, ревизия, стадия | Растр листа PDF (200 DPI) | Экспертная разметка полей | Per-field exact match |
| T2 | Марки/позиции/оси на поле чертежа | Растр фрагмента | Разметка (id, текст) | Recall@all + Token-F1 с пенализацией за пропуски (по Enginuity) |
| T3 | Таблицы (спецификации, ведомости) | Растр таблицы | Строки эталона (TSV) | Row-level recall + per-cell exact match |
| T4 | Деградированные сканы | T1–T3 с blur/rotate/noise аугментацией | Те же эталоны | Δ метрик к чистому варианту |

Корпус: fixture-листы из `samples/drawings/`, `samples/sections/`, `samples/specifications/` +
деградированные варианты. **До получения комплекта заказчика все вердикты — fixture-only.**

## Условия прогона (детерминизм)

- temperature 0, max_tokens фиксирован, единый prompt-шаблон на задачу;
- **обе** конверсии: ZS-Direct и ZS-CoT — Enginuity показал модельно-специфичную
  CoT-зависимость (GPT-5.2: +21пп recall от CoT; Qwen: нейтрально; Gemma Task-2: CoT вредит);
- полные request/response логи; пин снапшотов весов (sha256);
- вывод — JSON-схема с толерантным парсером; отказ парсинга = zero score, фиксируется отдельно.

## Статистика выбора (Waves K–M, обязательна)

1. Каждый прогон → артефакт `extraction_quality_report` (fixture = кластер).
2. Попарное сравнение моделей → `aerobim.tools.compare_extraction_runs`:
   paired permutation p-value + Holm-поправка по семейству метрик; primary
   endpoint — macro-F1 задачи T2 (марки) как ближайшей к продуктовой ценности.
3. Перекрывающиеся CI → «статистически неразличимы», выбор по
   вторичным критериям: VRAM, латентность, лицензия, устойчивость T4.
4. Точечные числа без CI в отчёт не выносятся.

## Чек-лист failure modes (из Enginuity Appendix C — проверять целенаправленно)

- [ ] partial-list truncation (обрыв длинных перечней);
- [ ] callout–part misalignment (сдвиг привязки позиции);
- [ ] paraphrase divergence (перефразирование обозначений — блокер для правил);
- [ ] schema deviation (невалидный JSON);
- [ ] quantity defaulting (дефолтные количества вместо прочитанных).

## Claim boundary (не подлежит пересмотру в этом протоколе)

- VLM — **только** вспомогательная подсветка/кандидаты; финальное замечание порождается
  детерминированным правилом и/или подтверждается экспертом (HITL);
- результаты на fixture-корпусе не переносятся на корпус заказчика (RT-001);
- «AI читает чертежи как инженер» — запрещённая формулировка (Claims Lock);
- выбор модели фиксируется отчётом с CI и p-values, а не «общим рейтингом».
