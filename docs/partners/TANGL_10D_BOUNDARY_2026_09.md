# Мы / Tangl / 10D

Интеграции с 10D и Tangl **нет и не обещаем**. П. 2.2.2 ответов 25.08: на MVP
достаточно файлового обмена. Связанный черновик файловой границы:
[`10D_OEM_PITCH_2026_09.md`](10D_OEM_PITCH_2026_09.md).

Публичные факты партнёра (их заявления, не наши замеры): Tangl — слой работы
с BIM-данными; 10D СОД — комплектность, маршруты, ЭЦП. «Проверить модель по
правилам» у них закрыто. Наша ниша — **шов между носителями**.

| Вопрос | Tangl (их контур) | 10D СОД (их контур) | AeroBIM |
|---|---|---|---|
| Что проверяет | Модель / наполнение / коллизии / EIR по **модели** | Наличие файла, маршрут, ЭЦП, комплектность пакета | Согласованность **содержимого**: модель ↔ лист ↔ ТЭП/ведомость ↔ ТЗ/ИТЗ ↔ записка ↔ смежный раздел |
| Комплектность «есть ли ПЗ» | не их главный вопрос | уже есть | не заявляем как фичу |
| Привязка к пункту ИТЗ/СТО/СП | их родная модель мышления | маршрут согласования | поле первого класса находки + колонка HTML/BCF `norm=` |
| Куда уходит замечание | возврат в среду проектирования / Excel | маршруты СОД | BCF 2.1/3.0 ZIP + HTML/JSON; импорт в их СОД **NOT_VERIFIED** |
| Прод-база 10D | — | их SaaS | не просим доступ; стоим сбоку |
| Native RVT/NWD | их контур authoring | — | жёсткий отказ; обмен IFC + PDF/A |
| Вердикт комплекта | отчёты модели | статус документа | `summary.passed` только движок (ADR-001); SKIPPED/FAILED видны |
| Повтор типовой секции | конструктор проверок | типовые маршруты | тот же IDS/профиль на следующем комплекте; эталон — их |

**Одна фраза на колле:** 10D СОД проверяет **наличие и маршрут** документа. Tangl
проверяет **модель**. Мы проверяем, что факты в разных файлах **не противоречат
друг другу**, и отдаём находку с пунктом нормы и GUID.

Регуляторный шов, который рынок уже назвал: расхождение XML-ведомости ТЭП и
геометрии IFC (АГР / доклад про ТЭП против модели). Это класс находки шва, не
«мы лучше Tangl».
