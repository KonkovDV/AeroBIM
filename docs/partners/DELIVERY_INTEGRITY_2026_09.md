# Целостность доставки результатов

На созвоне 09.09 заказчик (дважды) сообщил, что **результатов проверок не
видел**. Это P0: продукт без подтверждённой доставки не участвует в приёмке.

## Цепочка (обязательные шаги)

1. **Сформировано** — HTML краткая выжимка + JSON/BCF, `report_id`, git SHA
   (фиксированный, не «latest main»), профиль правил, хеш манифеста файлов.
2. **Отправлено** — владелец, не git. Канал: почта организаторов / согласованный
   контур. Вложение или ссылка с датой.
3. **Получено** — письменное «пакет от YYYY-MM-DD получен» от роли (не ФИО в git).
4. **Открыто** — тот же `report_id` / SHA, что в манифесте.
5. **Проверено** — named expert: подтверждено / ложно / не решено / новое.
6. **Решение зафиксировано** — дата и роль; молчание ≠ согласие.

Журнал живёт в gitignored `.local/partners/`. В git — только факт, что журнал
существует как процедура, без текста замечаний и имён файлов.

## Что не считать доставкой

- Коммит, PR, зелёный CI.
- Демо-seed overlay (`999…`) и учебный комплект.
- Скриншот без `report_id`.
- Пересказ в Telegram без манифеста.

проектов **и** пробный доступ, чтобы заказчик сам прогнал контрольные данные.
Прямого контакта с Самолётом нет. Это **финальная** дата для заказчика, не
прелюдия к коллу 15.09.

выжимка (включая «что не проверено»: PDF-таймауты, если карточки только

получение (`OA-25`). SBOM / checksum / restore — окно **19–21.09** (`OA-26`),
