## 2. Как давать доступ (выбор)

Прямого контакта с их ИТ нет. К **14.09** должен стоять путь, который
организаторы доведут сами.

**Рабочий к сроку — time-boxed HTTPS стенд оператора**

VPN или согласованный закрытый URL, персональный bearer, журнал входов.
Это не облачный SaaS. Облако на созвоне 09.09 отклонено.

**Если их контур примет образ — on-prem Docker**

1. `docker compose -f docker-compose.production.yml up --build` за reverse
   proxy с HTTPS. Токен **не** класть в `VITE_*`.
2. Две роли: Эксперт (правка замечания) и Пользователь (просмотр).
3. Review shell: `frontend/` `npm run build` за тем же proxy (compose
   production — API; UI отдельно). CLI: `python -m aerobim.tools.run_kt3_jury`
   не заменяет их самостоятельный analyze.
4. Offline image-track: [`../offline-deployment-2026.md`](../offline-deployment-2026.md).
   Bare-metal без Docker — не заявляется.

**Не годится как «самостоятельно проверить»**

Шаринг экрана. Демо-seed. Публичная ссылка на GitHub HTML. Анонимный доступ.
Колл **15.09** с менторами программы.

## 3. Что должно быть в каждом из трёх отчётов

- Секция `executive-brief` (найдено / не проверено / MEP NOT_VERIFIED).
- SKIPPED и advisory **не вырезаны**.
- `summary.passed` пишет движок, не LLM (ADR-001).
- Паспорт прогона: замер на этой машине, **не SLA**.
- Сверка расчёта: четыре строки, не solver.
- Native RVT/NWD/DWG — отдельная строка отказа.

Если IFC слота над SPF 256 МиБ — entity inventory / RocksDB, кап не
поднимать; в выжимке это сказано.
