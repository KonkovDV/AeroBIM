# Глоссарий для жюри (без внутреннего жаргона на первом экране)

| Термин в репо | По-русски для заявки |
|---|---|
| Checkpoint **NO_GO** | Не готов к **подписанию у заказчика**; система при этом работает на fixtures |
| RT-001 | Нет доказанной точности на **корпусе заказчика** и нет публичного корпуса «ПД РФ + заключение экспертизы». Внешний документный бенчмарк: AEC-Bench ([arXiv:2603.29199](https://arxiv.org/abs/2603.29199)) — инвентарь есть, ложные пропуски ещё не замерены |
| RT-002 | Нет **утверждённого профиля приёмки заказчика**. Официальные IDS Мособлгосэкспертизы есть ([moexp.ru ТИМ](https://www.moexp.ru/services/tekhnologii-informatsionnogo-modelirovaniya/)) |
| RT-003 | Нет заказной **федеративной** MEP-модели + правил |
| Claims Lock | Запрет заявлять недоказанное (не отказ от рыночного расчёта) |
| Shared-gate | Технический статус «проверки прошли»; не разрешение на стройку |
| `summary.passed` | Вердикт только детерминированного ядра |
| OFF==ON | Advisory-ИИ не меняет вердикт — машинно проверяемо |
| Fail-closed | Пропуск обязательной проверки → не «зелёный» отчёт |
| Provenance | У находки есть источники: лист / GUID / правило |
| Fixture GO | Доказано на тестовых комплектах репозитория |
| WP-01…08 | Внутренние инженерные пакеты авг 2026 — см. eng-статус |
| BCF T2 | Импорт замечаний в конкретную CDE заказчика — ещё не доказан |
| Open-core | Ядро открыто (MIT); контур / норм-паки / поддержка — коммерция |
| L1 open-bench | Открытый бенчмарк (например AECV ~0.43) ≠ точность продукта |
| macro_f1 ≈ 0.86 | Извлечение сущностей на русском **fixture**-корпусе ≠ RT-001 |
