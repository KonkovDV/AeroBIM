## В-4 — три варианта по DWG (выбрать один)

1. **Лицензия ODA** — деньги, строка ТЗ зелёная.  
2. **Конвертация с фиксацией потерь** — дёшево; в отчёте явно «что потеряли при конвертации».  
3. **Явный отказ** — IFC/PDF достаточны для проверки *комплекта*; DWG = вход в чужую специализацию.

Молчание / «fail-closed не заявляем» = худший вариант в чек-листе.

## В-6 — классы (черновик целей, не заявленные результаты)

| Класс ошибки | Черновая цель пилота | Комментарий |
|---|---|---|
| Отсутствующие / пустые атрибуты | высокая | Легко надуть агрегат |
| Расхождения размеров / площадей | средняя | Измеримо |
| Несогласованность разделов | осторожная | Самый жёсткий класс |
| Коллизии геометрии | по наличию пакета | |
| Расхождения с расчётом (сверка, не solver) | осторожная | |
| MEP системный clash | **не цель** до RT-003 | |

Агрегат 90% без пропорции классов = вопрос, который **задаём мы первыми**.

## P3-1 — вопрос Кортунову (отправить как есть)

> Михаил, короткий вопрос на слот, не презентация. У нас в публичном контуре порядка 48 портов, 67 адаптеров и 58 DI-токенов при трёх незакрытых блокерах (корпус заказчика, утверждённый норм-пак, федеративный MEP). Как вы это читаете для регулируемой отрасли — как зрелость контура под аудит или как переинжиниринг до продукта? Нам нужен ваш внешний вердикт, даже если он неприятный.

Любой ответ полезен: «переинжиниринг» → режем scope; «зрелость» → цитата на защиту.
