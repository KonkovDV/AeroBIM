# AeroBIM — one-pager (второе касание)

Для человека, который уже ответил на письмо или согласился на разбор.  
Не вставлять в первое холодное письмо.

## Кто мы

Команда AeroBIM, программа «Техлаб Москва» (Московский инновационный кластер),  
задача ГК «Самолёт». Открытое ядро: github.com/KonkovDV/AeroBIM.

Сопоставляем доступные источники комплекта и показываем расхождения  
со ссылкой на источник. Решение о годности документации остаётся за вашим специалистом.  
Не заменяем СОД, BIM-автор и эксперта: слой доказательной проверки одного согласованного сценария (сначала IFC + IDS). Клин: [`../partners/WEDGE_FREEZE_EVIDENCE_LAYER_2026_08_16.md`](../partners/WEDGE_FREEZE_EVIDENCE_LAYER_2026_08_16.md).

> Оператор (не в письмо): границы DWG / MEP / CDE — только если спросили, на звонке.  
> Не обещать точность, native DWG, системный MEP, импорт BCF в СОД, Checkpoint GO.

## Что предлагаем

**40 минут на вашей стороне.** Система локально (Docker). Вы загружаете  
один завершённый раздел (IFC + PDF с текстовым слоем; native DWG не обещаем).

- Если у вас **есть** эталон замечаний — сверим попадания / лишнее / пропуски. Это разбор, не заявленная точность продукта.  
- Если эталона **нет** — покажем finding с provenance (лист, GUID, правило). Вердикт оставляете вы.

Файлы не обязаны покидать периметр. Отчёт остаётся у вас при любом результате.  
`summary.passed=false` на учебном срезе — норма: Shared-gate fail-closed, не «продукт сломан».

Для проектной организации возможен тот же разбор на вашем архивном комплекте  
под вашим NDA.

## Что измеряем на разборе

Если эталон замечаний **есть:** совпадения, лишнее, пропуски, расхождение критичности. Это разбор, не dual-rater и не точность продукта.

Если эталона **нет:** один finding с provenance (лист, GUID, правило). Вердикт оставляете вы.

## Безопасность

По умолчанию — локальный контур. Облачная модель для ваших данных — только  
если вы явно разрешите отдельно.
