# Kimi K3 в трёхисточниковой программе (Самолёт × Техлаб × МИК)

Дополняет [study](KIMI_K3_INTEGRATION_STUDY_2026_07_27.md) и
[сценарную матрицу](KIMI_K3_SCENARIO_MATRIX_2026_07_27.md) третьим измерением:
как advisory-подключение K3 согласуется с **Техлабом** (жюри, do-not-claim) и
**МИК** (Фонд: программа испытаний, акт, воспроизводимость), не только с ТЗ
Самолёта. SSOT сторон: [`../tz/TRI_SOURCE_REQUIREMENTS_MATRIX_2026.md`](../tz/TRI_SOURCE_REQUIREMENTS_MATRIX_2026.md),
[`../partners/MIK_PILOT_COMPLIANCE_2026.md`](../partners/MIK_PILOT_COMPLIANCE_2026.md),
[`../partners/TECHLAB_TASK_07_READINESS_2026.md`](../partners/TECHLAB_TASK_07_READINESS_2026.md).

## Свежие якоря (июль 2026)

| Домен | Якорь | Перенос |
|---|---|---|
| Agentic AEC | **AEC-Bench** (arXiv:2603.29199, Nomic 2026) — 196 задач, 9 семейств, agentic-системы в AEC | ожидания калиброваны: agentic-VLM в AEC ещё оценочный фронт, не приёмка |
| Реальный кейс | Agentic roof-compliance (MDPI *Buildings* 16(13):2637, 2026) — VLM→структурные данные из чертежей | подтверждает роль VLM как экстрактора-кандидата, не решателя |
| Long-context «ловушка» | RAG-vs-LC 2026: эфф. ёмкость 60–70%, lost-in-the-middle (~30% просадки), 30–60× латентность, ~1250× стоимость | 1M-контекст K3 **не** дампить; retrieval → критично для SLA/стоимости акта МИК |
| Детерминизм-контур | Castagnone 2026 (MDPI *Buildings* 16(3):534) | вердикт у движка — совпадает с ADR-001 |

## 1. K3 ↔ обязательства МИК (Фонд)

| # | Ожидание МИК | Роль K3 | Правило |
|---|---|---|---|
| M3 Программа испытаний | K3 — опциональный advisory-инструмент в методике | Описывается как вспомогательный; не критерий |
| M4 План-график | Прогон VLM/OCR-протокола в окне 4–20 авг | Не на критическом пути вердикта |
| M5 Измеримые критерии | K3 **не** порождает собственную метрику в акт | Точность — только `evaluate_detection_precision` на adjudicated-корпусе |
| M6 Протоколы испытаний (воспроизводимость) | K3 `temperature=0` + пин снапшота (sha256) + полные request/response логи | Детерминизм прогона обязателен для Фонда; недетерминизм LLM — риск |
| M7 Акт/заключение площадки | K3 **не идёт строкой измеренного результата** без adjudication | «ни одна строка акта не сильнее intake-gates» — K3 подчиняется тому же правилу |
| Затраты (449-ПП) | Стоимость 2.8T max-effort (input/output токены, 1250× на 1M) | В смету — реалистичная модель стоимости; предпочесть малый Kimi-VL/retrieval |

**Ключ:** в акт МИК идёт то, что измерено на согласованном корпусе с
adjudication. K3 как advisory может поднять recall кандидатов и ускорить
черновики, но **сам по себе не является результатом акта** — он вход для
детерминированной проверки и эксперта.

## 2. K3 ↔ Техлаб (жюри программы)

| Критерий пилота | Взаимодействие K3 | Do-not-claim (обязательно) |
|---|---|---|
| SLA ≤30 мин | K3 вне критического пути (best-effort, таймаут) | не «K3 ускоряет приёмку» |
| TP/(TP+FP) ≥0.60 interim | K3-кандидаты → adjudication → harness | **не** «>90%», **не** precision K3 отдельно |
| Экономия ≥20% | Черновики замечаний + чтение сканов | замер vs baseline, не постулат |
| BCF в СОД | K3 обогащает описания топиков | не «BCF готов к СОД» |
| MVP-демо | K3 — advisory-слой поверх детерминизма | **не** «AI читает чертежи как инженер» |

Формулировки из анкеты Техлаба уже фиксируют: LLM/VLM — advisory, вердикт за
движком. Подключение K3 **не расширяет** заявку: та же граница, новый бэкенд
advisory-слоя. Любой публичный текст про K3 — через Claims Lock.

## 3. Разрешение конфликтов источников (для K3)

1. **0.60 (Техлаб) vs 0.90 (ТЗ P4)** — K3 не влияет: он advisory, точность
   меряется на adjudicated-корпусе независимо от того, был ли кандидат от K3.
2. **Календарь**: контент — окно Самолёта (4–20 авг протокол); форма/сроки —
   план-график МИК; K3-прогон вписан в оба, не блокирует ни один.
3. **Публичность**: жюри-пак Техлаба публичен — тексты про K3 в нём только
   Claims-Lock-safe; customer-данные и прогоны на них — NDA, вне git.

## 4. Развёртывание под грантовый (NDA) контур

- Открытые/fixture (бенчи Техлаба) → K3 API tier A через SSRF-гард — допустимо.
- NDA-комплект Самолёта под грантом МИК → публичный K3 API **запрещён**
  (`kimi_advisory_ready()` hard-disable под `samolet_pilot`/`production`);
  только малый Kimi-VL on-prem (tier C) или детерминизм-only.
- Реализация ([Wave T](../quality/KIMI_K3_ADVISORY_WAVE_2026_07_27.md)) уже
  кодирует этот fail-closed tier-гейт.

## 5. Явно НЕ заявляется

- K3 не появляется как измеренный результат в акте МИК без adjudication.
- K3 не нарушает Техлаб do-not-claim (нет «>90%», «читает как инженер», «CDE-ready»).
- K3 не меняет вердикт и не двигает Checkpoint (`NO_GO` до RT-001/002/003).
- Числа стоимости/латентности 1M — литературные оценки, не наш замер.
