# Qwen 3.8 и AeroBIM: что делать до КТ#2

## 0. Вывод в трёх строках

1. **Облачный `qwen3.8-max` подключать нельзя** — он ломает закрытый контур, воспроизводимость, 152-ФЗ и импортозамещение одновременно.
2. **Локальные открытые веса Qwen — нужно, и срочно.** ТЗ Самолёта прямо требует AI-функционал, а все четыре конкурента его показывают. Без видимого ИИ-контура AeroBIM теряет баллы там, где он архитектурно сильнее всех.
3. **Точка входа — не вердикт, а формулировка.** Модель пишет текст замечания по уже найденной детерминированной находке и компилирует ТЗ в требования. Это попадает ровно в критерии оценивания и не трогает `summary.passed`.

## 1. Что произошло 2 августа

Qwen официально выпустил **Qwen3.8-Max**: 2.4 трлн параметров, архитектурная база Qwen 3.5, мультимодальность (текст, изображения, видео, документы), контекст ~984K токенов. Впервые для Max-класса обещаны **открытые веса** — по анонсу команды, «на следующей неделе», плюс отдельно открывается **Qwen3.8-27B**. Открытые модели Qwen лицензируются под **Apache 2.0**.

Что важно для планирования:

| Факт | Следствие для AeroBIM |
|---|---|
| Веса Max ещё не выложены (обещание, не релиз) | Планировать нельзя. В бандл КТ#2 не попадёт. |
| 2.4T параметров | Даже после выкладки — неразворачиваемо в контуре заказчика |
| Qwen3.8-27B открывается вместе с Max | **Это и есть целевая модель.** Плотная 27B ставится на одну карту |
| Preview-эндпоинт Max доступен только по подписке Token Plan ($6/$18/$68), отдельной цены за токен нет | Бюджет непрогнозируем, эндпоинт «непрерывно обновляется» |
| Model Studio API совместим с OpenAI и Anthropic | Адаптер — две строки конфига, если он вообще понадобится |
| Доступно уже сегодня и стабильно: Qwen3.6-27B, Qwen3.6-35B-A3B, Qwen3.5 | **Начинать надо с них, не дожидаясь 3.8** |

Отдельно: в вашей же презентации от 17 июля (слайды 04 и 06) Qwen-VL уже стоит на roadmap. То есть это не новое решение, а выбор чекпоинта и момента.

## 2. Что требует ТЗ Самолёта — и где там место модели

ТЗ Задачи №7 в разделе «Функциональность» выделяет **AI-функционал отдельным пунктом**: Computer Vision для анализа чертежей, OCR для извлечения текста, NLP для анализа ТЗ и генерации замечаний. В критериях оценивания стоит «качество генерации замечаний (RU/EN)».

Разложим требования ТЗ по исполнителям:

| Требование ТЗ | Кто должен исполнять | Роль Qwen |
|---|---|---|
| Обработка 2D чертежей (векторных) | Геометрический движок (PDF-вектор → DXF → IFC) | **Нет** |
| Обработка 2D чертежей (сканированных) | OCR + VLM на region-crop | **Да, ключевая** |
| Извлечение объектов, размеров, аннотаций | VLM предлагает → детерминированный верификатор подтверждает | **Да, кандидаты** |
| Обработка BIM (геометрия + атрибуты) | IfcOpenShell | **Нет** |
| Коллизии, точность > 90% | IfcClash, геометрия | **Категорически нет** |
| Расчётные ошибки | Сверка ЦИМ ↔ расчётная схема (SAF 2.0 / ЛИРА) | **Нет** |
| Некорректные площади | Геометрия + ε-band | **Нет** |
| «Неэффективное использование пространства» | Единственный по-настоящему оценочный пункт ТЗ | **Да, advisory** |
| Несогласованность между разделами | Cross-doc движок | Нормализация формулировок |
| Соответствие ТЗ (RU/EN) | ТЗ → машиночитаемые требования | **Да, компилятор с верификатором** |
| Генерация текстов замечаний RU/EN | — | **Да, прямое попадание в критерий** |
| Возможность редактирования комментариев | HITL, уже есть | Модель даёт черновик |
| ≤ 30 мин на комплект | Бюджет времени | Ограничение, а не помощь |

**Главный вывод раздела.** Из тринадцати требований модель уместна в пяти, и ни в одном из них она не касается вердикта. Три из этих пяти — прямые пункты критериев оценивания. Это редкий случай, когда «правильно» и «выгодно на защите» совпадают.

Ещё одна деталь ТЗ, которую стоит использовать: в ограничениях прямо написано «**ограниченный объём обучающих данных**». Это официальный аргумент заказчика в пользу few-shot LLM вместо обучения CV-модели с нуля. Его можно цитировать на защите.

## 3. Три способа подключения и вердикт по каждому

### Вариант A. Облачный `qwen3.8-max` через Alibaba Cloud Model Studio — **НЕТ**

Пять независимых причин, каждой достаточно:

1. **Ваша собственная политика маршрутизации это запрещает.** По матрице `data_classification.py` IFC, чертежи и расчёты — `CONFIDENTIAL`, данные заказчика / НДА / «Самолёт» / нормопак — `RESTRICTED`. Для обоих PUBLIC-egress = `BLOCKED`. Маскирование в вашей же документации помечено как «не доказательство анонимности».
2. **Закрытый контур.** Слайд 11 презентации обещает «без обязательного вывода моделей наружу». Облачный вызов это обещание отменяет. Плюс деградация доступа из РФ к зарубежным сервисам — риск, который вскроется не на демо, а на КТ#3.
3. **Воспроизводимость.** У вас есть run manifest, reproducibility hash, `REPRODUCIBILITY-2026.md`, CITATION.cff. Preview-эндпоинт официально «непрерывно обновляется». Один и тот же прогон через месяц даст другой ответ — и FAIR-заявка рассыпается.
4. **Правовой контур.** ПД под УКЭП по ФЗ-309 (с 01.03.2026): исходники нельзя менять, а передача за пределы контура — отдельный разговор со службой ИБ, который вы не выиграете за две недели.
5. **Импортозамещение.** Конкурент AI Project Control прямо заявляет полностью российский стек на Yandex Cloud. Вызов китайского облака из решения для Самолёта — подарок оппоненту на защите.

Держите профиль `public_qwen38_max` в конфиге со статусом `NOT_VERIFIED` и жёстким `PUBLIC`-only. Не удаляйте — но и не включайте.

### Вариант B. Локальные открытые веса — **ДА, это целевой контур**

Что ставить и когда:

- **Сейчас (4–10 августа):** `Qwen3.6-27B` или `Qwen3.6-35B-A3B` под vLLM/SGLang. Веса есть, Apache 2.0, работает сегодня.
- **Сентябрь, если веса выйдут и пройдут SBOM/license-гейт:** миграция на `Qwen3.8-27B`. Апгрейд должен быть сменой строки в provider-конфиге, не рефакторингом.
- **Никогда:** `Qwen3.8-Max` 2.4T локально. Это датацентр, а не контур девелопера.

Почему локальные веса решают сразу несколько ваших проблем:

- **Воспроизводимость становится сильнее, а не слабее.** Пин чекпоинта по SHA-256, `temperature=0`, фиксированный seed, хеш модели в run manifest. Это ровно то, чего облако дать не может, — и это отдельный слайд на защите.
- **Оффлайн-бандл.** Веса Q4-квантованной 27B — порядка 17 ГБ, bf16 — порядка 55 ГБ. Кладётся в тот же tarball, что и Docker-образ. Зеркало — ModelScope, он доступнее Hugging Face из РФ.
- **Ноль egress.** Гейт `HybridRouteGate` при локальном маршруте перестаёт быть теоретическим ограничением и становится реально проходимым путём.

### Вариант C. Qwen как инструмент разработки — **ДА, немедленно, без интеграции**

Репозиторий публичный и MIT. Qwen Code / Qwen3.8-Max в Qwen Studio на кодовой базе AeroBIM не нарушает никакой политики данных. Написание адаптеров, тестов, доков, разбор дифов — до КТ#2 это самый дешёвый источник скорости. Никакого интеграционного долга.

## 4. Куда именно вставляется в код

Хорошая новость: обвязка уже построена, писать почти нечего.

**Что уже есть в репозитории:**
- `domain/hybrid/data_classification.py` — 5 уровней, дефолт `CONFIDENTIAL`, `most_restrictive` на агрегате
- `domain/hybrid/trust_policy.py` — `decide_route`, fail-closed
- `domain/hybrid/privacy_guard.py` — per-tenant HMAC-токены, restore-таблица
- `domain/hybrid/model_router.py` — профили провайдеров, включая `local_vlm` / `private_vlm`
- `application/services/hybrid_route_gate.py` — advisory pre-gate на Analyze (WP-02)
- `core/config/settings.py` — `hybrid_provider_config_path`
- `core/di/tokens.py` + `bootstrap.py` — `HYBRID_ROUTE_GATE`, `HYBRID_MODEL_ROUTER`
- Тест `test_advisory_vlm_off_equals_on` — доказательство `OFF == ON`

**Что нужно добавить:**

1. Профиль `private_qwen_local` в provider-конфиг: base URL локального vLLM, `temperature=0`, `seed`, пин чекпоинта по хешу, таймаут в рамках stage timeout budget.
2. Адаптер `infrastructure/adapters/qwen_local_adapter.py` под OpenAI-совместимый эндпоинт vLLM. Строгая выходная JSON-схема, fail-closed при отклонении — механика уже описана в вашем threat model (§18, output-as-data + schema guard).
3. Регистрация в `bootstrap_container()` + новый DI-токен.
4. Отражение в `/v1/system/capabilities` со статусом `ok` / `skipped` / `failed`. При недоступности модели — `SKIPPED`, не `FAILED` (advisory-контур не должен ронять вердикт).
5. Запись в `audit_event`: имя модели, хеш весов, версия промпта, длина входа, факт локального маршрута. Секреты не логировать.
6. Хеш модели и версия промпта — в run manifest, рядом с reproducibility hash.
7. Регресс: `test_advisory_vlm_off_equals_on` расширить на новый профиль. Провал этого теста = блок мерджа.

**Оценка трудозатрат:** 2–4 дня на пункты 1–7, если vLLM уже поднят.

## 5. Три конкретных сценария применения

Расставлены по возрастанию риска. Делайте строго по порядку.

### 5.1. Генератор формулировок замечаний (RU/EN) — **риск нулевой**

**Как работает.** Детерминированный движок нашёл находку: `finding_id`, `source_id`, `evidence_refs`, ссылка на пункт нормы, координаты зоны. Модель получает **только структурированную находку** и пишет человеческий текст замечания на RU или EN. Модель не видит ни IFC, ни чертежа, ни расчёта.

**Почему безопасно.** Находка уже существует до вызова модели. Модель физически не может создать, удалить или переклассифицировать находку. `verdict_impact = none` не просто задекларирован — он структурно невозможен.

**Почему выгодно.** Это прямой критерий оценивания ТЗ. И это то, чем участники задачи с сильным remark-quality / полевым контуром сейчас выигрывают на демо: у них замечание читается как написанное инженером, а не как строка лога.

**Классификация данных.** Находка без исходников — `INTERNAL` при обезличивании. Локальный маршрут проходит по политике без оговорок.

### 5.2. Компилятор «ТЗ → машиночитаемые требования» — **риск низкий, ценность высокая**

**Как работает.** Текст ТЗ или регламента → модель предлагает кандидатные требования в структуре RASE → **детерминированный верификатор** проверяет: XML-валидность, XSD-валидность, исполнимость как IDS. Невалидное отбрасывается или уходит в repair-loop. Принятое требование попадает в экспертный журнал WP-04 и активируется только после подтверждения человеком.

**Почему это правильный паттерн.** Модель предлагает, верификатор проверяет, эксперт решает — ровно ваш слайд 04. Похожий конвейер уже опубликован peer-reviewed (ИТМО, ICDM Workshops 2025: 138 экспертных требований, ~100% XML-valid, ~94% XSD-valid, ~78% исполнимых). То есть подход не гипотетический, и вас с ним всё равно сравнят.

**Связь с блокерами.** Это прямая работа по RT-002. Не закрывает его (нормопак должен быть утверждён заказчиком), но превращает «нормопак — synthetic» в «нормопак — компилируется из утверждённого текста за часы».

**Осторожно:** активное правило без подписи эксперта — это `NOT_VERIFIED`. Никогда не позволяйте скомпилированному правилу влиять на вердикт до подтверждения.

### 5.3. VLM на region-crop сканированных чертежей — **риск средний, делать последним**

**Как работает.** Не целый лист. Только вырезанный регион: штамп, экспликация, размерная цепочка, спецификация. Модель возвращает распознанное содержимое в строгой схеме, детерминированный нормализатор приводит к типам, найденное сверяется с IFC (как уже сделано в P2-04: claimed GUID → `ifc_guid` только после подтверждения по пространственному индексу).

**Почему это закрывает ваш единственный `MISSING`.** «Human-level CV / drawing literacy: MISSING» — это единственная позиция в вашей матрице возможностей, где стоит честное «отсутствует». ТЗ требует Computer Vision явно. Есть участники потока, чей продукт построен целиком вокруг CV по чертежам.

**Неожиданный бонус — extraction integrity.** У вас есть риск расхождения render-vs-extract (невидимый текст, font-decoding splits, reading-order splits). VLM, читающий **отрисованную** страницу, даёт независимый второй сигнал против текстового слоя. Расхождение → `WARNING` в `EXTRACTION_INTEGRITY`. Это не просто закрытие дыры, это функция, которой нет ни у кого из четвёрки.

**Жёсткие ограничения:**
- Целый лист или комплект наружу — никогда, даже на локальный маршрут без нужды.
- `geometry_verified` остаётся `False`. VLM не измеряет.
- Crop — производный артефакт. Оригинал под УКЭП не трогается, provenance фиксирует происхождение crop от исходного файла по хешу.

## 8. Формулировки для Claims Lock

**Разрешено говорить:**
- «Локальная open-weight модель (Apache 2.0) применяется как advisory-генератор формулировок замечаний и кандидатных требований»
- «Вердикт формируется детерминированным движком; включение и выключение вспомогательного ИИ не меняет `summary.passed` — доказано регрессионным тестом»
- «Внешний сетевой выход отсутствует; веса поставляются в составе оффлайн-бандла, чекпоинт зафиксирован по хешу»
- «Все сгенерированные тексты помечены как машинно-сгенерированные и требуют подтверждения эксперта»

**Запрещено до появления доказательств:**
- «ИИ проверяет нормы» — правило должно быть исполняемым, а не интерпретируемым
- «Модель понимает чертёж» — OCR и VLM не равны инженерному пониманию
- «Точность модели выше 90%»
- «Qwen 3.8 в продукте» — пока веса не в бандле, не в SBOM и не прошли лицензионный гейт
- «Автоматическая генерация замечаний» без указания на обязательное подтверждение экспертом

## 9. Что осознанно не делаем

| Идея | Почему нет |
|---|---|
| Дообучение / fine-tune под AEC | Ограниченный корпус, потеря воспроизводимости, ваш же принцип «новая ошибка становится тестом и правилом, а не бесконтрольным дообучением» |
| Модель выбирает маршрут или инструмент | Запрещено по построению вашего threat model. Не начинать. |
| GraphRAG поверх нормативной базы | Соблазнительно, но IFC KG у вас `advisory scaffold`. Сначала P0 на живом пути. |
| Агентный автономный проход по комплекту | P3 по вашей же дорожной карте. До подтверждённого P0 — не начинать. |
| Показывать вывод модели как находку на демо | Мгновенно обнуляет главный дифференциатор AeroBIM |

## 10. Финальная оценка целесообразности

**Подключать — да, но не то и не туда, куда тянет заголовок релиза.**

Qwen 3.8-Max как облачный сервис не решает ни одной вашей задачи и создаёт пять новых проблем. Qwen 3.8-27B (или сегодняшний 3.6) как локальные открытые веса закрывает три пункта ТЗ, один из которых — прямой критерий оценивания, и при этом усиливает, а не ослабляет вашу позицию по воспроизводимости и закрытому контуру.

Ни один вариант не двигает чекпойнт с NO_GO: RT-001, RT-002 и RT-003 — внешние артефакты, кодом и моделью не добываются. Но RT-002 после сценария 5.2 перестаёт быть работой на недели и становится работой на часы после получения утверждённого текста норм.

**Главный риск проекта по-прежнему не в модели.** Он в развёртывании внутри контура и в гигиене зависимостей. Модель — это то, что добавит баллов на защите. Оффлайн-бандл — это то, без чего защиты не будет.
