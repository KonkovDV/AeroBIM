# GUID в ГОСТ Р 21.101-2026 и контракт находки AeroBIM

## Пункт стандарта (по тексту)

**ГОСТ Р 21.101-2026**, раздел **8.2** (комплектование электронной документации), пункт **8.2.4**:

> Каждый документ, добавляемый в ПДЭ, должен иметь глобальный уникальный идентификатор (GUID), с помощью которого допускается однозначно идентифицировать документ для отслеживания его изменений при последующей передаче новых версий ПДЭ. Идентификатор назначают автоматизированным способом… Изменение идентификатора для новых версий ДЭ при формировании новых версий ПДЭ недопустимо.

Связанный контекст: **8.2.3** — реквизитная часть ПДЭ = `info.xml` с атрибутами документов/папок.

**Не заявляем:** соответствие ГОСТ целиком; юридическую валидность УКЭП; что наш model-element GUID = document GUID из 8.2.4 без маппинга.

## Как это стыкуется с AeroBIM

| 21.101-2026 п. 8.2.4 | AeroBIM (уже) |
|---|---|
| Устойчивый GUID документа для отслеживания изменений версий | Provenance находки до устойчивого идентификатора элемента/источника (GUID в IFC / source ref) |
| GUID не меняется при новой версии ДЭ | Identity vs revision: логический документ стабилен; revision merge fail-closed (`ingestion.py`) |
| Машиночитаемый пакет (`info.xml`) | Structured findings + BCF + hash chain |

Это **совпадение механизма** (устойчивый ID для версий/изменений), а не сертификация продукта.

## Фраза для питча / холодного контакта

«С апреля 2026 национальный стандарт (ГОСТ Р 21.101-2026, п. 8.2.4) требует GUID для отслеживания изменений электронных документов — AeroBIM с первого дня строил находки на устойчивых идентификаторах модели и источнике.»
