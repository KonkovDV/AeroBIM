## Статусы (четыре)

| Код | Смысл |
|---|---|
| **обнаруживается** | Проверка есть и может сработать на типичном открытом пакете (IFC + IDS + PDF/аннотации + calc как evidence) **без** customer-approved norm-pack |
| **обнаруживается условно** | Нужны названные исходные данные или утверждённый норм-пак / оба раздела / явный scope |
| **вне области** | Требует инженерного суждения эксперта, а не сверки артефактов |
| **не обнаруживается** | Нет runtime-пути (или запрещён Claims Lock: решатель, native DWG, MEP system-clash as OK) |

## Вывод (честный)

1. Это **карта покрытия** против внешнего человеческого перечня КР, а не измерение точности и не «сколько норм в базе».  
2. **0 %** позиций КР-перечня закрываются «из коробки» без специальных исходных данных или утверждённого норм-пака.  
3. **42 %** — условно достижимы: completeness, cross-doc АР↔КР, IDS/свойства, customer-approved norm-pack.  
4. **33 %** — зона эксперта (суждение, достаточность, влияние на соседнюю застройку).  
5. **25 %** — принципиально вне контура (решатель МКЭ / полнота расчётных случаев / реестр устаревших норм без данных заказчика).  
6. Сравнение с маркетингом «N норм загружено»: наша таблица отвечает на вопрос «какие **типовые замечания экспертизы** мы вообще можем адресовать», и ответ проверяем по строкам.
