## 4. Что означает «точность выше 90%»

Предложение методики (не заявка цифры):

1. Раздельные **precision** и **recall**, не один агрегат.  
2. Измерение **по классам ошибок** с собственными целевыми значениями: геометрические коллизии; расхождения размеров; площади и количества; несогласованность между разделами; отсутствующие элементы; расхождения с расчётом (evidence match ≠ solver); нарушения нормативных требований.  
3. Отдельный порог **recall по критическим**.  
4. Размер выборки + **Wilson CI**; планировщик в `compute_quality_protocol_stats`.  
5. Двойная слепая разметка + процедура разрешения разногласий (`QUALITY_MEASUREMENT_PROTOCOL_2026_08.md`).  
6. Учёт пропусков (FN); отложенная выборка; воспроизводимость (commit, hash комплекта, оборудование).  
7. Протокол замера времени: состав комплекта, hash, cold/warm, machine fingerprint.

Отраслевая закономерность: 90 % на отсутствующих атрибутах достигается тривиально; 90 % на логической несогласованности между разделами не достигнуто никем — агрегат всегда вытягивается лёгкими классами. Поэтому «>90%» без разбивки по классам **не принимается** как критерий приёмки.

Опора: WP-07 · `PrecisionClaim.publishable` · `measure_package_sla` · протокол качества.
