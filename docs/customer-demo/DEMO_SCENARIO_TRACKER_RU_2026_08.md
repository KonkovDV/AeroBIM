# Сценарий демо — сравнение с заключением экспертизы

**Задача трекера №4:** прогон на данных завершённого проекта и сравнение с фактическим заключением экспертизы по **количеству** и **критичности** замечаний.

Полный протокол (EN/техника): [`completed-project-comparison-protocol.md`](completed-project-comparison-protocol.md)

## Вход (обязателен)

1. Комплект завершённого проекта (IFC + PDF/РД + ТЗ + расчёты) — NDA.  
2. Заключение экспертизы **или** внутренний реестр замечаний.  
3. Согласованная шкала критичности (наша CRITICAL/WARNING/INFO ↔ шкала заказчика).

## 25-минутный сценарий

| Мин | Шаг | Что видно |
|---:|---|---|
| 0–3 | Состав комплекта + хеши файлов | intake / completeness |
| 3–8 | Показать реестр экспертизы (без AeroBIM) | baseline эксперта |
| 8–14 | Детерминированный прогон | findings + evidence (лист / GUID) |
| 14–17 | Карта покрытия | «не проверялось» ≠ «ок» |
| 17–22 | Сопоставление: matched / только экспертиза / только AeroBIM | таблица |
| 22–25 | Разбор **AI-only** на 3 класса | см. ниже |

## Три класса «только AeroBIM» (обязательно)

| Класс | Смысл |
|---|---|
| `false_positive` | ложное срабатывание |
| `non_essential` | реально, но верно не вошло в формальное заключение |
| `expert_miss` | реально и пропущено реестром — сильнейший аргумент пилота |

**Без этой разметки заказчиком цифры сравнения не публикуем.**

## Что не говорим на демо

- «точность >90%»  
- «MEP delivered» / native DWG  
- AECV 0,43 как продуктовая точность  
- fixture SLA как SLA Самолёта
