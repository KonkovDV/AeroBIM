# Фронтенд AeroBIM: внешний обзор интерфейса

**Версия:** 1.0.0 · **Дата:** 10.09.2026 · **Срез:** `main@9ef3af47`
**Объект:** `frontend/src` — оболочка рабочего места эксперта (review shell).
**Кому адресован:** ИТ-ментор МИК, жюри КТ#3, внутренняя команда.

---

## 1. Рамка утверждений

Документ оценивает **интерфейс**, а не точность проверок. Здесь нет и не может быть
утверждений о полноте находок, времени прогона и приёмке заказчиком.

- `customer_go=false`, `customer_acceptance=NOT_EVALUATED`;
- `accuracy_claim=NOT_ESTABLISHED`, `sla_claim=NOT_ESTABLISHED`;
- ни одно решение этого обзора не меняет `summary.passed`;
- время работы эксперта в интерфейсе **не измерено** на данных заказчика; любые
  оценки удобства ниже — экспертные, а не замеренные.

## 2. Метод

1. Прочитаны файлы оболочки на срезе `main`: `App.tsx`, `main.tsx`,
   `features/shell/*`, `lib/ui-copy.ts`, `lib/i18n/*`, слои
   `styles/visual-language/01…09`, тесты-контракты (`app-shell-boundary`,
   `color-scheme`, `token-contrast`, `html-shell-security`), `scripts/lint-ui-strings.mjs`.
2. Каждое решение сопоставлено с внешним эталоном (раздел 3), а не с вкусом.
3. Каждая находка получила статус: закрыта в этом PR, вынесена в бэклог или
   отнесена к пилоту (проверяется только на людях заказчика).

Ограничение метода: браузерный прогон и axe-скан выполняются в CI, локально
недоступны `vitest`/`vite`; визуальные наблюдения сделаны по исходникам стилей.

## 3. Эталоны (состояние на сентябрь 2026)

| Источник | Требование, которое мы берём | Как применяем |
| --- | --- | --- |
| Apple HIG, Accessibility | Управление доступно с клавиатуры, состояния озвучиваются | Пропуск навигации, `role="status"` для смены плотности |
| Apple HIG, Motion | Уважать «уменьшить движение» | Уже есть в `08-polish.css`, не дублируем |
| WCAG 2.2, 2.4.1 | Механизм пропуска повторяющихся блоков | `.skip-to-work` → `#work-area` |
| WCAG 2.2, 2.4.11 | Фокус не перекрыт залипающей шапкой | `scroll-margin-block-start` у цели пропуска |
| WCAG 2.2, 2.5.8 | Цель нажатия не меньше 24×24 CSS-px | Поле `--vl-target-min` для кнопок и `select` |
| EAA (применение с 28.06.2025) | Доступность как условие поставки в ЕС | Держим WCAG 2.2 AA как рабочий минимум |
| Практика корпоративных таблиц (Carbon и обзоры 2025–2026) | Две-три ступени плотности, липкая шапка, числа вправо, виртуализация от ~1000 строк | Плотность закрыта, липкая шапка и виртуализация — в бэклоге |
| Solibri, BIMcollab, Revizto, Navisworks | Разбор идёт списком с фильтрами и переходом «находка → место в модели» | Подтверждает выбранную схему «список + деталь + вьюер» |

## 4. Что оболочка уже делает правильно

- **Одна светлая тема, зафиксированная контрактом.** Тёмная схема отключена
  осознанно (WP-FE-25): отчёт печатают и показывают на проекторе. Контраст токенов
  проверяется тестом, а не на глаз.
- **Русский язык интерфейса под линтером.** `scripts/lint-ui-strings.mjs` не даёт
  латинской прозе просочиться в подписи — важно для приёмки регламентом.
- **Панели честности встроены в поток работы.** Ограничения показываются рядом с
  результатом, а не в сноске.
- **Клавиатурный разбор.** Горячие клавиши, окно помощи, диалог о несохранённом
  замечании — это то, чего нет у большинства «просмотрщиков отчётов».
- **Кольцо фокуса двухтональное**, есть `prefers-contrast: more` и `forced-colors`.

## 6. Что закрыто в этом PR

- `lib/ui-density.ts` — две ступени плотности, выбор живёт в `localStorage`,
  применяется до первой отрисовки, переживает запрет хранилища;
- `components/DensityToggle.tsx` — переключатель в шапке с `aria-pressed` и
  озвучиванием текущей ступени;
- `styles/visual-language/10-ergonomics.css` — поле цели 24 px, 44 px для сенсорного
  ввода, пропуск навигации, компактный шаг только по `data-density="compact"`;
- `App.tsx` — явная цель `#work-area` с запасом прокрутки под липкой шапкой;
- `ergonomics-contract.test.ts` — контракт: порядок слоёв, размеры целей, наличие
  пропуска, **запрет сжимать или скрывать панели честности**.

Что **не** менялось намеренно: тема, токены текста и контраста, порядок импортов
стилей, состав панелей честности, ни одна строка про вердикт.

## 8. Как проверять

1. `npm run lint` — латинская проза в подписях запрещена.
2. `npm test` — `ui-density.test.ts` и `ergonomics-contract.test.ts` вместе с
   существующими контрактами оболочки.
3. `npm run build` — типы и сборка.
4. Вручную: `Tab` от загрузки страницы → первым виден пропуск навигации; переключение
   плотности не меняет кегль и не скрывает панели честности; печать страницы
   выдаёт тот же состав блоков.

## 9. Что нельзя утверждать по итогам обзора

- что интерфейс «удобен» — это покажет только ревью эксперта заказчика;
- что доступность соответствует WCAG 2.2 AA целиком — проверены отдельные критерии,
  полный аудит не проводился;
- что изменения ускоряют разбор — время не измерено.
