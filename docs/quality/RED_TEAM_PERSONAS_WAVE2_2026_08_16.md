## 2. ИТ-ментор (энтерпрайз-архитектор заказчика)

**Атаки:**

1. **«SSO? У вас auth_bff=NOT_IMPLEMENTED»** — phase 3 лабораторная, production IdP не подключён. Ответ: план phase 4 + static bearer для пилота; но строка «SSO в пилоте = статический токен» должна прозвучать самому, заранее.
2. **«Ресурсный профиль?»** LRU-8 кэш IFC-моделей хорош против утечки, но ментор спросит: сколько RAM на типовой федеративный пакет? Числа нет. Ответ: замер на fixture + верхняя граница из `max_upload_bytes` × 8 — опубликовать как требование к ВМ.
3. **«Миграции БД в рантайме»** (`ALTER TABLE IF NOT EXISTS` на старте) — для АИТ это анти-паттерн: нужны права DDL и непредсказуемость при схеме. Ответ: вынести в отдельный шаг развёртывания до КТ#3.
4. **«Наблюдаемость?»** Структурные логи есть, correlation-id есть; метрик/SLO/алертов нет. Пилот переживёт; энтерпрайз-контур — нет.
5. **«DR/бэкапы?»** RPO/RTO не сформулированы; Redis-jobs и FS-storage — single-node по умолчанию.
6. **«Кто пентестил?»** SSRF-jail/path-jail самописные и хороши, но внешней проверки не было. Ответ: публичный repo + bug-bounty нет — предложить заказчику пентест в пилоте как часть профиля приёмки (сильный ход: самим попросить).
7. **«Интеграционный контракт 10D»** — file/API boundary из «Анализ 2» §8 описан, но OpenAPI intake-контракта с полями project_id/package_id/revision… в пакете нет (`docs/openapi.json` — про текущие ручки, не про 10D-контракт). До КТ#2 — одна страница контракта в KT2-пакете.

**Вердикт ментора:** ядро готово к защищаемому пилоту в контуре «одна ВМ + Docker + статический токен»; до энтерпрайз-контура — SSO, метрики, DR, миграции. Не врать про это — и пилот получаем.
