## 3. White Hat: данные, речь, git

1. **Режим данных (OA-9).** До письменного ответа производные канала в git
   не кладём. Внутренние регламенты (не ПД/РД) из контура проверки исключены
   локально; в чат — факт исключения, не просьба «удалите у себя».
2. **LLM-egress.** На профиле заказчика исходящий advisory запрещён.
   Формула: «со своей стороны запрещаем; просим письменно зафиксировать».
   Не OpenAI/Anthropic как exhibit.
3. **Хеш.** Публикация агрегата без `pack_hash` / fingerprint машины ломает
   SLA-claim gate. Просить разрешение на хеш пакета и профиля — хеш не
   раскрывает содержимое.
4. **Шифры и локаторы.** В git — метки комплектов A/B/C. URL шары — никогда.
5. **Публичные поверхности.** README, TIER0, submission — речевая формула
   КТ#2/честность. OEM-черновик — не лицо репозитория
   ([`../partners/10D_OEM_PITCH_2026_09.md`](../partners/10D_OEM_PITCH_2026_09.md)).
6. **Юрлицо / приз.** Git не регистрирует ИП и не обещает выплату. Если
   юрлица нет — это блокер **владельца**, не строка плана в git как факт.
