## Слайд 2. Зачем это рынку

Каждый файл открывается. Комплект при этом противоречит сам себе.

Нормоконтроль и экспертиза жгут дни на шов: площадь в модели, на листе и в ТЗ — три разных мира. Арматура в расчёте, сети в Navisworks, в IFC — пусто.

С 1 октября 2026 Сингапур (CORENET X) требует IFC-проверку на новых проектах GFA ≥ 5 000 м², не на все объекты. В России тот же класс работы всё ещё делают руками. Tangl и Solibri сидят **в модели**. 10D ведёт **документ**. Мы сидим **на шве между файлами**.

*Голос:* не «мы лучше Тangla». Другая полка. Их не подменяем.

## Слайд 3. Что умеем сегодня

Три полки: СОД ведёт маршрут. Checker читает модель. AeroBIM ловит расхождение комплекта.

Вердикт — детерминированный слой (ADR-001). Нейросеть его не подписывает. ИИ — извлечение и подсказки, не формула «ИИ не нужна». Обязательная проверка, которая не прошла, роняет комплект.

На входе — IFC, PDF и офисные листы. На выходе — JSON, HTML и файл BCF. Контур — Docker без сети. Вашу платформу дорабатывать не нужно.

Публичные IDS экспертизы: 50 наборов, 847 спецификаций. Из них 24 файла Мособлгосэкспертизы — 389 спецификаций.

*Голос:* учебный прогон сейчас. Их IDS в контуре — следующий подписанный шаг, не обещание с трибуны.

## Слайд 5. Как измеряем и как берём приз

Пилот с правилом до прогона: промежуточная точность 0,60 на выборке **111**.

Метрика эффекта P3 — **число межфайловых расхождений на комплект до экспертизы**, не «точность продукта».

Если доверительный интервал проседает ниже 0,50 — сужаем область. Цифру не докручиваем.

Цепочка Фонда: программа испытаний → соглашение → методика → акт. Формы — у оператора Фонда. Партнёр подписывает приложения.

Приз этой задачи — **оплачиваемый пилот**, 1 место, по Положению. Конкретные условия — отдельным соглашением.

*Голос для кресла Фонда:* мы не просим форму акта у заказчика канала. Мы просим форму у вас.

## Слайд 7. Демо и запрос

Двадцать секунд: `python -m aerobim.tools.run_kt3_jury` → находка с GUID → файл BCF.

Учебный комплект из git. На учебной фикстуре отказ комплекта — штатный сценарий.

Чтобы блок эффекта стал вашим, а не моделью, нужны три числа (роль: **инженер нормоконтроля / ГИП комплекта**; фамилию валидатора не выдумываем):

1. Рабочие дни одного круга согласования РД по типовой секции.
2. Часы ручной проверки того же комплекта.
3. Сколько лишних кругов вы сами считаете нормой.

Плюс письменный режим данных по каналу от 25 августа.

*Голос:* молчание не читаем как согласие с цифрой из брифа. Порог пилота — 0,60 по методике, либо ваш иной порог письмом.

## Приложение. Только оператору, не на экран

Самооценка по ГОСТ Р 58048 — **TRL 4** (лаборатория). Уровень 5 не заявляем. Это самооценка, а не независимая экспертиза.

Если спросят чужие цифры с деки 13.09:

- 0,4325 — доля точных совпадений на открытом бенче (`macro_extended`), не F1.
- 0,86 F1 — учебный корпус извлечения, не точность на комплекте заказчика.
- 837 пересечений — открытая модель duplex, не АР↔ИОС канала.
- 62 — расчёт мощности; для ширины интервала пилота — **111**.
- КР 4/24 ≈ 16,7 % — карта покрытия, не recall продукта.
- 389 спецификаций — 24 файла МОГЭ, не все 50 наборов.
- Вход по их IdP сегодня отвечает 501. Файл BCF — не запись в их СОД.

Оператору, не на кадр:

- 30 минут — цель ТЗ. На учебной стенке есть p95 = 0,0746 минуты, но при `sample_n = 1`: p95 равен максимуму. Масштаб inventory на публичных XSD не делает из этого SLA заказчика. Флаг `sla_pass` не переносится.
- Целевая полнота >0,90 — горизонт протокола после корпуса, не текущий замер. Пилот — 0,60. Десять убитых мутаций на стенке+IDS — синтетика; нижняя граница Wilson ≈ 0,72. В `accuracy-answer-2026-09.json` та же строка пока показывает фикстурный 1/8 — расхождение разведено в триаже, на кадр не выносим.
- Рынок 50–55 млрд ₽ — верхняя граница оценок обзора; консенсус участников около 38 млрд ₽ при росте 10–15 %.
- BCF в СОД: журнала импорта (лог, снимок, хеши) нет. ZIP 2.1/3.0 — структурный файл. В тексте замечания — абзацы на русском и английском.
- Хранение: диск отчётов и IFC-маркеры; SQLite по желанию; объектное хранилище. Redis не обязателен. Фоновые задачи идут в процессе API, отдельная очередь работников не заявлена.
- Ядро MIT; IDS профиль — данные, не форк. PyMuPDF — отдельный extra, не в основном контуре.
- Набросок людей: 2 инженера + 0,5 HITL. План — GitHub Issues, не Гант.
- Ритм КТ#1–КТ#3: контрольные точки, не новый дедлайн 29–30.09.
- Дата регистрации юрлица — не выдумывать.
- Weekly `NO_GO` августа — исторический pin, не живой продукт. Живой Checkpoint — GO; `customer_go` false.
