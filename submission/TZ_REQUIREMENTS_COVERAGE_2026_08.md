# Покрытие требований ТЗ

Источник: ТЗ «Система автоматизированной верификации проектной и рабочей документации». Назначающая сторона в публичном дереве не называется. Checkpoint `GO`. `customer_go` false.

Словарь статусов: `реализовано на фикстуре` — работает на учебных данных, на комплекте заказчика не измерено · `частично` — есть базовый контур · `advisory` — есть, но не влияет на вердикт · `не реализовано` — отсутствует · `ждёт заказчика` — нет подписанного профиля, двух разметчиков или комплекта одной ревизии.

Снимок возможностей на учебной стенке: [`tz-matrix-status-latest.json`](../docs/evidence/tz-matrix-status-latest.json).

## 1. Термины

| Термин ТЗ | Что у нас | Статус |
|---|---|---|
| OCR | Растровый контур PDF + распознавание текста | частично |
| Computer Vision | Слой подсказок по чертежу; в вердикт не входит | advisory |
| NLP | Извлечение из ТЗ и расчётов, генерация текста замечаний | частично |
| BIM-модель | IFC через IfcOpenShell: атрибуты, пространственный индекс, AABB. Площадь по солиду IfcSpace не считаем | реализовано |

Разбор: [`TZ_COMPLIANCE_MATRIX_2026.md`](../docs/tz/TZ_COMPLIANCE_MATRIX_2026.md) §1.

## 2. Концепция — ассистент, а не замена эксперта

Технический статус комплекта ставят детерминированные движки. Языковые и визуальные модели только подсказывают. При расхождении побеждает движок. Правило: [`ADR-001`](../docs/architecture/ADR-001-verdict-ownership-2026.md).

## 3. Целевые задачи

### 3.1 Анализ графических данных

| Требование | Реализация | Статус |
|---|---|---|
| 2D-чертежи (вектор) | Разбор структурированных аннотаций PDF | на фикстуре |
| 2D-чертежи (сканы) | Растр + распознавание текста | частично |
| BIM-модели | Разбор IFC2X3 / IFC4 / IFC4X3 на фикстурах; канал задачи — IFC2X3. IFC4X3 против IDS IFC4 — отказ по умолчанию | реализовано |
| Извлечение объектов | Классы IFC + пространственная структура | на фикстуре |
| Извлечение размеров | Сверка величин с учётом единиц | на фикстуре |
| Текстовые аннотации | Аннотации PDF + распознавание | частично |

### 3.2 Сверка документации

| Требование | Реализация | Статус |
|---|---|---|
| С результатами расчётов | Сверка переданных результатов; собственного решателя нет | на фикстуре |
| С техническим заданием | Извлечение требований и сопоставление с моделью | частично |
| Разделов между собой | Межразделная сверка с фиксацией обеих сторон | на фикстуре |
| С нормами | IDS и нормо-паки; профиль приёмки заказчика не подписан | ждёт заказчика |

Полноты «всех норм» не заявляем. Машиночитаемо проверяется то, что выражено в IDS или rule pack.

### 3.3 Выявление ошибок

| Требование | Реализация | Статус |
|---|---|---|
| Пересечения инженерных систем | Контур коллизий есть; системный clash на комплекте заказчика не подтверждён | ждёт заказчика |
| Геометрические конфликты в BIM | AABB на учебной фикстуре: precision=1.0, recall=1.0, **n=6** (6 confirmed overlaps / 16 walls). Duplex AABB **654** — inventory, `geometry_verified=false`, не та метрика. Это не «коллизии по ТЗ >90%» | на фикстуре |
| Расчётные ошибки | Сверка результатов и исходных данных; независимая перепроверка не реализована | частично |
| Некорректные площади | Сверка QTO, если атрибут заполнен. Площадь по геометрии IfcSpace в коде — `not_implemented` (16 152 пустых NetFloorArea — класс дефекта, не посчитанная площадь) | на фикстуре |
| Неэффективное использование пространства | Автоматической метрики нет | не реализовано |

### 3.4 Логические несоответствия

| Требование | Реализация | Статус |
|---|---|---|
| Несогласованность между разделами | Конфликт с доказательствами обеих сторон | на фикстуре |
| Отсутствующие элементы | IDS + комплектность пакета | на фикстуре |
| Расхождения размеров | Сверка с нормализацией единиц | на фикстуре |

### 3.5 Поддержка эксперта

| Требование | Реализация | Статус |
|---|---|---|
| Подсветка проблемных зон | Текст находки и карточка — да. Наложение рамки на лист — P1-smoke на фикстуре; в рабочем месте эксперта подсветки на листе нет | частично |
| Генерация текста замечаний | Шаблоны RU/EN; этаж/ось из индекса IFC | на фикстуре |
| Редактирование комментариев | Правка в интерфейсе | реализовано |

## 6. Критерии оценивания

**Ни одно целевое значение ТЗ не измерено на комплекте заказчика.** Нет независимого размеченного корпуса и двух разметчиков.

| Критерий ТЗ | Целевое значение ТЗ | Наше состояние |
|---|---|---|
| Выявление коллизий | точность >90% | Метод готов; на учебной модели пересечения измерены; на данных заказчика — не измерено |
| Выявление расчётных ошибок | — | Сверка результатов; независимого решателя нет |
| Выявление несоответствий | точность >90% | Метод готов; на данных заказчика — не измерено |
| Качество замечаний (RU/EN) | — | Шаблоны с доказательствами |
| Стабильность | — | Повторный прогон даёт совпадающий хеш детерминированных находок |
| Скорость обработки комплекта | до 30 минут | На учебном комплекте — порядок секунд. Целевое значение ТЗ на комплекте заказчика не измерено |
| Снижение когнитивной нагрузки | — | Приоритизация, доказательство рядом с находкой |

Как будем мерить после получения комплекта: [`QUALITY_MEASUREMENT_PROTOCOL_2026_08.md`](../docs/pilot/QUALITY_MEASUREMENT_PROTOCOL_2026_08.md).
