# Прототип

Запускается из репозитория одной командой на учебном комплекте. Данных заказчика в дереве нет.

## Быстрый запуск (основной путь)

```bash
cd backend
pip install -e ".[dev,raster]"
python -m aerobim.tools.run_demo_ifc_acceptance_gate
```

На выходе — `artifacts/ifc-acceptance-gate-demo/`: `acceptance-gate.json`, `report.html`, `report.json`, `findings.bcfzip`.

Что показывает прогон: IFC + IDS → находка с GUID элемента, идентификатором правила, парой expected/observed и ссылками на доказательства; сводный `summary.passed` выставлен детерминированным контуром; блок `capabilities` честно перечисляет, что было проверено, а что пропущено.

## Дополнительные сценарии

| Команда | Что демонстрирует |
|---|---|
| `python -m aerobim.tools.run_demo_ifc_acceptance_gate` | **Основной показ:** IFC + IDS → находка с доказательствами, `summary.passed=false` на учебном комплекте |
| `python -m aerobim.tools.run_demo_vertical_slice` | Оверлей (P1): проблемная зона наложена на PDF-чертёж детерминированными рамками |
| `python -m aerobim.tools.measure_package_sla` | Измерение времени обработки комплекта по протоколу |
| `python -m aerobim.tools.evaluate_detection_precision` | Расчёт TP/FP по размеченному набору |
| `python -m aerobim.tools.validate_dwg_toolchain` | Честный отчёт: чтение DWG без конвертации — `NOT_IMPLEMENTED` |
| `python -m aerobim.tools.verify_kt2_handoff` | Самопроверка пакета КТ#2 |

## Веб-интерфейс

```bash
cd frontend
npm install
npm run dev
```

Просмотр модели IFC в 3D, наложение ошибок на 2D-чертёж, список замечаний с фильтрацией и приоритизацией, редактор текста замечания с сохранением решения эксперта.

API и контракты: живая схема на `GET /openapi.json` запущенного сервиса (генерируется `backend/scripts/export_openapi.py`; сгенерированные дампы в репозиторий не коммитятся). Загрузка комплекта — `POST /v1/uploads` (multipart).

## Что прототип делает честно

| Поведение | Почему это важно жюри |
|---|---|
| Пропуск обязательной проверки роняет комплект | «Нет находок» не значит «проверено»: если обязательная проверка не прошла, комплект в отказе |
| Несовпадение схемы IFC и версии в IDS — ошибка | Чужая схема не проходит молча |
| Модели не меняют технический статус | Языковая или визуальная модель не может превратить отказ в успех |
| Воспроизводимость | Повторный прогон даёт тот же `reproducibility_hash` по детерминированным находкам |
| Конфликт документов не «разрешается» автоматически | Показываются обе стороны и доказательства; решает эксперт |

## Границы прототипа

Чтение DWG без конвертации — не реализовано. Системные коллизии MEP — `NOT_VERIFIED`. Импорт BCF в СОД заказчика — `NOT_VERIFIED` (структурный ZIP формируется). Независимого расчётного решателя нет: сверяем переданные результаты с источниками. Компьютерное зрение и языковые модели только подсказывают, вердикт не меняют.
